# The Curatool — Draft & Setup UX Revisions Plan

This plan describes six related changes to the setup/draft experience. Each item lists the
goal, the affected files, the concrete implementation approach, and acceptance criteria so it
can be executed independently. The items are ordered to minimise rework (shared offer/curate
refactors come before randomisation tuning).

---

## Context / Current State (verified)

- **Setup page** ([Setup.razor](src/TheCuratool.Web/Components/Pages/Setup.razor)) already exposes
  *Use Marionette* and *Legion game* as toggles driven by
  [`DraftSessionState`](src/TheCuratool.Web/Services/DraftSessionState.cs) and persisted via
  [`SessionSetupOptions`](src/TheCuratool.Application/SessionSetupOptions.cs) →
  [`GameSession`](src/TheCuratool.Domain/GameSession.cs) →
  [`GameSessionEntity`](src/TheCuratool.Infrastructure/Entities/GameSessionEntity.cs).
- **Atheist** is currently handled mid-draft through a *Confirm Atheist Commitment* button on
  [Draft.razor](src/TheCuratool.Web/Components/Pages/Draft.razor) → `ConfirmAtheistCommitmentAsync`
  → `DraftEngine.ConfirmAtheistCommitment`, which sets `IsAtheistCommitmentConfirmed` on the
  current unchosen slot. The [`AtheistFirstPickConstraint`](src/TheCuratool.Domain/AtheistFirstPickConstraint.cs)
  only allows the Atheist on the very first pick (or when drunk-flagged).
- **Lil' Monsta** ([`MinionSwapSetupRule`](src/TheCuratool.Domain/MinionSwapSetupRule.cs)) only adjusts
  the distribution (+1 Minion / −1 Demon) *after* it is chosen, not while it merely sits on the script.
- **Curate UI** uses per-character checkboxes plus a separate "special role" dropdown, plus an
  *Add Evil option* checkbox (`AddEvilOptionToCuratedOffer`) and an `EvilSentinelCharacterId` ("evil").
- **Alchemist/Boffin** dynamic abilities are resolved through a post-choice *Assign Borrowed Ability*
  panel on Draft.razor (`PendingDynamicAbilityDraftOrder`), except when pre-selected during curate.
- **Random 3** is generated by `DraftEngine.SuggestThree`, which deterministically takes the *first*
  valid option of each type ordered by type then display name — so repeated draws show identical
  Outsider/Minion picks.
- **Legion mode** already collapses evil seats into an "evil" sentinel inside
  `GetRemainingValidCharacters`, but the curate flow exposes a manual *Add Evil option* instead.

## Item 1 — Move Atheist to Setup as a "Use Atheist" toggle

**Goal:** Add a *Use Atheist* option to the Setup page (mirroring *Use Marionette*). When enabled,
at least one player must end up as the sober (non-drunk) Atheist; every target distribution is
otherwise valid (storyteller may freely deviate). Remove the *Confirm Atheist Commitment* button
from the Draft page.

**Approach:**
- Add `UseAtheist` to `SessionSetupOptions`, `GameSession`, `GameSessionEntity` (+ EF mapping/migration),
  and `DraftSessionState` (with a `SupportsAtheistCommitment`-style `SupportsAtheistOption` gate based
  on `ScriptContainsCharacter("atheist")`).
- Add a *Use Atheist* `InputCheckbox` to [Setup.razor](src/TheCuratool.Web/Components/Pages/Setup.razor)
  shown only when `SupportsAtheistOption`, wired to recalculation like Marionette.
- **Distribution semantics (tightened):** the Atheist means *there are no evil players* — the ST runs
  the whole game. So when `UseAtheist` is set, `SetupCalculator` produces a **single** target
  distribution: the standard distribution for the player count with **Minions = 0 and Demons = 0**,
  and the freed evil seats folded into the good team. Concretely, take the base
  `(T, O, M, D)` for the player count and yield `(T + M + D, O, 0, 0)` (Townsfolk absorb the former
  evil seats; Outsider count is unchanged and filled normally). This is **not** "any arbitrary
  T/O/M/D combination" — it is one specific all-good layout. The ST may still deviate manually at the
  table, but the tool presents and validates against this single canonical Atheist distribution.
- **Formula input (raw base distribution):** the `(T + M + D, O, 0, 0)` formula is computed from the
  **raw player-count base distribution only**, *before* any in-script setup rules are applied (Baron,
  Godfather, Lil' Monsta, etc.). In an Atheist game there are no real evil characters, so those rules
  are irrelevant and must be skipped — applying them first (e.g. a Baron's +2 Outsiders) would corrupt
  the canonical layout. Implementation: when `UseAtheist` is set, short-circuit the normal
  rule-application loop in `Calculate` and emit the single transformed base distribution directly. The
  base table guarantees `T + M + D >= 0`, so this can never produce negative Townsfolk.
- **Sober-Atheist enforcement:** separately from the distribution, `DraftEngine` enforces that the
  draft cannot *complete* until at least one seat is the **sober (non-drunk-flagged) Atheist**. A
  drunk-flagged Atheist does not satisfy the requirement.
- **`AtheistFirstPickConstraint` retirement (explicit):** the old first-pick/commitment constraint is
  fully removed from the Atheist's runtime behaviour. Pool eligibility is now driven solely by
  `UseAtheist`:
  - When `UseAtheist = true`: the Atheist is offerable at any point in the draft (no first-pick
    restriction); completion is gated on the sober-Atheist seat above.
  - When `UseAtheist = false`: the Atheist is **excluded from the draft pool entirely**, even if it is
    on the script. There is no half-retired fallback to the old first-pick constraint. Exclude it in
    `GetRemainingValidCharacters` (alongside the existing draft-excluded handling) when the session
    does not use the Atheist option.
  - Remove/neutralise the `AtheistFirstPickConstraint` data wiring in `characters.json`/`CharacterDatabase`
    so no stale first-pick logic remains; delete the constraint class if it is no longer referenced.
- Remove the *Confirm Atheist Commitment* button + `ConfirmAtheist`/`SupportsAtheistCommitment` usage
  from [Draft.razor](src/TheCuratool.Web/Components/Pages/Draft.razor); retire
  `DraftEngine.ConfirmAtheistCommitment` and `IsAtheistCommitmentConfirmed` plumbing.

**Acceptance:**
- Setup shows *Use Atheist* only when Atheist is on the script.
- With *Use Atheist* on: the single all-good `(T+M+D, O, 0, 0)` distribution is shown, the Atheist is
  offerable at any pick, and the draft cannot complete without a sober Atheist seat.
- With *Use Atheist* off: the Atheist never appears in offers/curate, with no first-pick fallback.
- Draft page no longer shows *Confirm Atheist Commitment*.

## Item 2 — Lil' Monsta adds a valid distribution while on script

**Goal:** If Lil' Monsta is on the script, `+1 Minion / −1 Demon` is a valid *target* distribution
even before it is chosen (so the base set offered/validated includes the swapped layout).

**Approach:**
- In [`SetupCalculator`](src/TheCuratool.Application/SetupCalculator.cs) `Calculate`, when the script
  contains `lilmonsta`, branch the base distribution to include both the unmodified distribution and
  the Lil' Monsta–swapped distribution (apply the `MinionSwap` adjustment as an additional starting
  outcome), then run remaining rules over both.
- Ensure the swap is only added once and never produces negative counts.
- **Interaction with Item 1 (`UseAtheist`):** this Lil' Monsta branch **must not fire when**
  `UseAtheist = true`. In a no-evil Atheist game the canonical distribution already has Demons = 0, so
  a `+1 Minion / −1 Demon` swap is meaningless and would yield a negative Demon count. Because Item 1
  short-circuits `Calculate` to emit only the single `(T+M+D, O, 0, 0)` layout, the Lil' Monsta branch
  is naturally bypassed — but state this explicitly: the swapped row is added **only** when
  `UseAtheist = false`. (The Item 2 negative-count guard is a secondary safety net, not the primary
  mechanism.)

**Acceptance:**
- A script containing Lil' Monsta yields both the standard `(T,O,M,D)` and the `(T,O,M+1,D-1)` target
  rows in valid target distributions, independent of whether Lil' Monsta has been picked.

## Item 3 — Replace curate checkboxes with the role dropdown

**Goal:** Remove the per-character checkbox grid in the curate panel. Use the existing "special role"
dropdown style as the single selection mechanism: a first dropdown lists every offerable role
(normal + special). If a *normal* role is chosen, no second dropdown is shown or required.

**Approach:**
- In [Draft.razor](src/TheCuratool.Web/Components/Pages/Draft.razor) curate section, delete the
  `selection-box` checkbox `@foreach` over `CurrentValidCharacters`.
- Build a unified role dropdown: populate from `CurrentValidCharacters` (normal roles) plus the
  special roles already enumerated (Drunk/Lunatic/Alchemist/Boffin) when each `CanUse…` gate is true.
- Only render the second dropdown (disguise / borrowed ability) when the selected role is special
  (i.e. requires a secondary value); for normal roles, *Add* directly appends `OfferOption.Normal`.
- Update `DraftSessionState.AddCuratedSpecialOption` (and add a normal-add path) so a single
  "Add role" action handles both normal and special selections, preserving the 1–3 cap.

**Acceptance:**
- Curate panel shows one role dropdown; a second dropdown appears only for special roles.
- Adding a normal role requires no second selection; the curated list/cap still works.

## Item 4 — Auto-assign Alchemist/Boffin ability from Random 3

**Goal:** Remove the post-choice *Assign Borrowed Ability* box. When Random 3 yields the Alchemist or
Boffin and it is chosen, immediately assign a valid borrowed ability automatically.

**Approach:**
- In [`DraftSessionState.RecordChoiceAsync`](src/TheCuratool.Web/Services/DraftSessionState.cs), when
  the chosen character `IsDynamicSetup` and no pre-selected ability exists, query
  `GetDynamicAbilityOptions(slot)`, select an available ability, and call
  `AssignDynamicAbilityAsync` immediately instead of setting `PendingDynamicAbilityDraftOrder`.
- Remove the *Assign Borrowed Ability* `<section>` and `PickDynamicAbility` UI from
  [Draft.razor](src/TheCuratool.Web/Components/Pages/Draft.razor). Keep `AssignDynamicAbility` engine
  logic for internal use; retire `PendingDynamicAbilityDraftOrder` UI surface.
- **Selection decision (firm):** the auto-assignment **randomly** picks among the `IsAvailable`
  abilities using `Random.Shared`, *not* the first-by-display-name option. This is consistent with
  Item 5's variety goal and prevents the Alchemist/Boffin from repeatedly borrowing the same ability
  across random draws. (Pre-selected curate abilities are unaffected — they remain deterministic.)
  Reuse a shared random-pick helper with Item 5 where practical.

**Acceptance:**
- Choosing an Alchemist/Boffin via Random 3 never shows a follow-up assignment panel.
- A valid (feasible) borrowed ability is assigned automatically and reflected in the summary counts.
- Repeated auto-assignments vary when more than one feasible ability exists.

## Item 5 — Add randomisation to Random 3 for subsequent draws

**Goal:** Repeated Random 3 draws for the same slot should vary the Outsider/Minion/etc. choices
instead of always returning the first option per type.

**Approach:**
- In [`DraftEngine.SuggestThree`](src/TheCuratool.Application/DraftEngine.cs), replace the
  "`FirstOrDefault` per type" selection with a *random* pick from the eligible options of each type
  (using `Random.Shared`), and shuffle the fallback fill loop.
- Keep the one-per-type variety preference (per Copilot instruction: SuggestThree variety is a
  preference, not enforcement) while randomising *which* option of each type is taken.

**Acceptance:**
- Drawing Random 3 multiple times for the same slot produces differing Outsider/Minion picks across
  draws when more than one candidate of that type exists.

## Item 6 — Remove "Add Evil option"; Legion-aware evil display

**Goal:** Remove the *Add Evil option* checkbox. If Legion is on the script, present all evil roles as
a single *Evil* (actual role hidden). If Legion is **not** on the script, show the explicit Minion or
Demon role instead.

**Approach:**
- Remove `AddEvilOptionToCuratedOffer`, `SetAddEvilOptionToCuratedOffer`, `OnAddEvilOptionChanged`,
  and the related checkbox/`EvilCurationLimitMessage` cap logic from
  [Draft.razor](src/TheCuratool.Web/Components/Pages/Draft.razor) and
  [`DraftSessionState`](src/TheCuratool.Web/Services/DraftSessionState.cs).
- Drive the "evil" sentinel purely from `IsLegionGame`: the existing Legion branch in
  `GetRemainingValidCharacters` already emits the `evil` sentinel — ensure curate/offer + display
  (`FormatOfferOption`, `ResolvePresentedCharacters`, `CreateEvilSentinelCharacter`) only collapse to
  *Evil* when `session.IsLegionGame`.
- When not a Legion game, ensure evil roles surface as their explicit Minion/Demon entries in offers
  and curate (no sentinel collapsing).
- **Forced-Lunatic carve-out (must preserve):** the Lunatic disguise offer is a *separate* mechanism
  from the Legion evil sentinel and must continue to work on **non-Legion** scripts. The Lunatic is an
  Outsider that is presented behind a Demon-type token (`OfferOption("lunatic", IsLunatic, disguiseId)`
  via `BuildSpecialDisguiseOfferOptions`), including the forced edge case where the Demon slot is
  already filled and the Lunatic is the only remaining Outsider candidate. Removing the *Add Evil*
  mechanism must **not** touch or suppress this path: only the `AddEvilOptionToCuratedOffer` /
  `EvilSentinelCharacterId` curate flow is removed. Lunatic (and Drunk) disguise offers, their
  special display (`(lunatic)` / `(drunk)`), and their feasibility handling remain intact and are
  independent of `IsLegionGame`.

**Acceptance:**
- No *Add Evil option* checkbox remains.
- Legion script: evil seats display as *Evil*; non-Legion script: explicit Minion/Demon shown.
- Lunatic disguise offers (incl. the forced-Lunatic edge case) still appear and display correctly on
  non-Legion scripts after the *Add Evil* removal.
